# SafeCircle

A responsive personal safety companion with private accounts, trusted contacts, a manual SOS workflow, browser-based location sharing, check-in reminders, a private incident timeline, a non-predictive risk-awareness prototype, and an optional aggregate-only admin endpoint.

## Demo additions

- **Siren:** SOS asks for confirmation, then starts a browser-generated siren for up to two minutes. Use the Stop siren button to stop it sooner. Device volume, silent mode, and browser support affect sound; do not rely on it as the only way to get help.
- **Six-language talk demo:** the scripted assistant can display and speak demo replies in English, Hindi, Spanish, French, Arabic, and Bengali. Speech input is optional and starts only after tapping the microphone. Browser speech recognition support varies, and the browser/provider may process microphone audio. SafeCircle does not save raw audio or send it to the API. Typed/spoken transcripts remain in this page's memory until reload/close. Replies are scripted rather than generated by an AI model.
- **Responder demo:** confirmed SOS location snapshots appear in a simulated feed alongside the trusted contacts' names. The feed and coordinates exist only in page memory and are cleared on reload or close. Forwarding chat requires a separate confirmation. No SMS, police station, or emergency service receives anything. Real SMS delivery is not configured.
- **Quick exit:** replaces the page with a blank tab. It does not erase browser history, server access logs, or information already captured by the operating system.
- **Phone install:** the site includes a web app manifest and service worker. On a supported phone, use the browser's Add to Home Screen / Install option. The shell can open offline, but sign-in, account data, and API features require a connection.

## What the SOS does

SOS is always a user-started action, requires a confirmation, requests browser location only at that moment, and records an incident without saving coordinates. If Web Share is supported, the app prepares a message for the user to choose a recipient and send; otherwise it copies the message for the user to send. SafeCircle never sends a message or call by itself, cannot contact police/emergency services, does not dispatch responders, and cannot guarantee that anyone sees the alert. For immediate danger, call your local emergency number directly.

Location is never collected in the background. Browser permission is requested only after a user action. Coordinates are used to create a one-time map link or a temporary local demo preview and are discarded by the API; this is not continuous or live tracking. Check-in timers run in the current browser tab and are not monitored; closing the tab can stop them. The “Safety reflection” is a private, non-predictive risk-awareness prototype. It is a simple self-report interaction, not an AI model, and makes no claim to detect or predict danger. No raw audio is saved by SafeCircle. Activity records are automatically deleted after 90 days. Contact information is kept until the user removes it or deletes their database.

## Run locally

Requirements: Node.js 20+ and Python 3.11+.

1. Copy `.env.example` to `.env` and set `SECRET_KEY` to a securely generated random secret of at least 32 characters. Keep it private.
2. Install Python dependencies: `python -m pip install -r requirements.txt`.
3. In one terminal, run the API: `uvicorn backend.main:app --reload --port 8000 --env-file .env`.
4. In another terminal, install frontend dependencies with `npm install`, then start Vite with `npm run dev`. Vite forwards `/api` requests to the local API on port 8000.
5. Open `http://localhost:5173`. Set `FRONTEND_ORIGINS=http://localhost:5173` for the API process. To point the frontend at a non-proxied API, set `VITE_API_URL` before the frontend build.

API documentation is available at `/docs` while the API runs.

## Deploy with Docker Compose

1. On a server with Docker Compose, create a `.env` file containing `SECRET_KEY` (generate a random secret of 32+ characters), and optionally `ADMIN_EMAILS`.
2. Set `FRONTEND_ORIGINS` to the public origin that serves the app. The included container serves the UI and API on the same origin, so use `FRONTEND_ORIGINS=http://localhost:8000` for local smoke testing. For production, configure HTTPS at your hosting reverse proxy and set the origin to the public HTTPS domain.
3. Run `docker compose up --build -d`. The SQLite database persists in the named `safecircle-data` volume.
4. Configure TLS at the host/load balancer. Browser location and clipboard/share functionality require a secure context (HTTPS, or localhost). Back up the persistent data volume securely.

## Deploy on Render

The `render.yaml` Blueprint configures this Docker app with a generated secret, health check, and a 1 GB persistent disk mounted at `/data`. In Render, create a Blueprint from a connected Git repository containing this project and review the service/disk cost before applying it. Render Free web services do not support persistent disks, so the included SQLite configuration uses the paid `starter` service plan. After Render reports the service is live, its dashboard shows the public `onrender.com` URL. Keep `DATABASE_PATH=/data/safecircle.db` so account and contact data persists.

For separate frontend and API hosting, serve the `dist` folder produced by `npm run build`, set the frontend build variable `VITE_API_URL` to the API origin, set API `FRONTEND_ORIGINS` to the frontend's exact HTTPS origin, and mount persistent storage at `DATABASE_PATH`. SQLite is suitable for a single API instance with durable local storage; use a managed database and migration plan before horizontal scaling.

## Environment variables

| Variable | Required | Purpose |
| --- | --- | --- |
| `SECRET_KEY` | Yes | HMAC signing key for bearer sessions; use a private random value of 32+ characters. |
| `DATABASE_PATH` | No | SQLite file path; defaults to `./data/safecircle.db`. Persist this file/volume. |
| `FRONTEND_ORIGINS` | No | Comma-separated exact allowed browser origins; defaults to local Vite. |
| `TOKEN_TTL_SECONDS` | No | Session lifetime in seconds; defaults to 86400. |
| `ADMIN_EMAILS` | No | Explicit email allowlist for aggregate-only admin counts. Leave blank to disable admin access. |
| `VITE_API_URL` | No | Frontend build-time API base URL; blank uses same-origin routes. |

## Privacy and production notes

Passwords are stored as PBKDF2-HMAC-SHA256 hashes with per-user random salts; the client stores a short-lived bearer token in local storage. Serve only over HTTPS in production, restrict CORS to the frontend origin, protect and back up the database volume, and provide a deletion process for account/contact data. Admin endpoint exposes only aggregate counts and requires an email in `ADMIN_EMAILS`. It is not an emergency response dashboard. Use a reviewed hosted identity provider and stronger abuse controls before a public launch. Never represent this prototype as a substitute for emergency services.

## Tests and build

Run frontend production build: `npm run build`.
Run backend checks: `python -m unittest discover -s tests`.
The API uses SQLite and can be tested with FastAPI TestClient.
